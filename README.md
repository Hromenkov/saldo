# Сальдо

Система обліку для малого бізнесу. Публікується на Netlify (finance.ukrai.org) автоматично з гілки main.

- `/` — система (React + TypeScript, Vite)
- `/landing` — лендинг
- `/legacy` — попередня версія прототипу одним HTML-файлом, для порівняння

## Розробка

```
npm install
npm run dev      # локально на http://localhost:5173
npm run build    # збірка в dist/
```

## Структура

- `src/data.ts` — демо-дані (документи, банк, звіти, каталоги для онбордингу)
- `src/store.tsx` — стан застосунку і навігація
- `src/views/` — сторінки: огляд, питання, документи, банк, ОСВ, закриття місяця, звітність, типові операції, структура
- `src/components/` — помічник, онбординг, панелі й діалоги
- `src/styles.css` — стилі (перенесені з прототипу без змін)

## Розпізнавання документів і імпорт з 1С

- **PDF і фото** надсилаються на `/api/recognize` (Netlify Function `netlify/functions/recognize.mts`). Вона читає документ через Claude API і повертає поля за схемою `src/recognize/schema.ts`. Перевірки (контрольна сума ЄДРПОУ/ІПН, арифметика, ПДВ, дублікати) робить код у `src/recognize/checks.ts`, не модель.
- Потрібна змінна середовища **`ANTHROPIC_API_KEY`** у налаштуваннях сайту Netlify (Site configuration → Environment variables). Без неї функція відповідає «Розпізнавання ще не підключене».
- Підтверджений рахунок для контрагента запам'ятовується як правило (`src/recognize/rules.ts`, поки в localStorage браузера).
- Номенклатура: кожен рядок товарної накладної прив'язується до позиції нашого довідника (`src/recognize/nomenclature.ts`). Прив'язка запам'ятовується для пари «код постачальника + його назва», тож «Ковб. Моск. в/к ТМ Глобино» і «Колбаса Московская» стають однією позицією. Схожа назва лише пропонується, накладну не можна провести, поки всі рядки не прив'язані. Довідник лише доповнюється: позиції не видаляються, а архівуються. Синхронізація з BAS через EnterpriseData (`Справочник.Номенклатура` і рядки документів): оновлення за кодом BAS, помітка на видалення стає архівом.
- **Вивантаження з 1С/BAS** читаються прямо в браузері (`src/import1c`): виписка `1CClientBankExchange` (.txt, UTF-8 або windows-1251), EnterpriseData (.xml), оборотно-сальдова відомість (.xlsx або .csv).
- Перевірка типів функції: `npm run check:functions`.

## План рахунків

`src/recognize/chart.ts` містить план рахунків (Інструкція 291) і допустимі кореспонденції Дт/Кт: закупівлі, ПДВ (6441 → 6442 → 6412), продажі, зарплату (661, 6411 ПДФО, 642 ВЗ, 651 ЄСВ), капітал (40/46), ОЗ і амортизацію (152 → 10x → 131, 976), кредити (501/601/611, 951/684), курсові різниці (714/945, 744/974), податок на прибуток і розподіл прибутку (981, 441/443, 671).

- Рахунок витрат (23, 91, 92, 93, 949) система лише пропонує. Затверджує бухгалтер, і після цього для контрагента діє правило.
- Рахунок має відповідати виду документа: товари йдуть на 201/281/22/152, послуги на 23/91/92/93/949, продаж на 701/702/703.
- Картка не дає провести документ, якщо в проводках є рахунок поза планом або недопустима пара.
- `npm test` перевіряє всі шаблони операцій, демо-документи і проводки розпізнавання. Ця перевірка входить у `npm run build`, тож зламаний шаблон не потрапить на сайт.

## ПДВ

`src/vat/rules.ts` — податкові накладні й розрахунки коригування, ЄРПН, СЕА ПДВ і чернетка декларації. Сторінка «ПДВ» у ролі бухгалтера (`src/views/Vat.tsx`).

- **Перша подія** (п. 187.1 ПКУ): по кожному договору накопичуються відвантаження і оплати, база ПН = більше з двох. Аванс дає ПН одразу (Дт 643 Кт 6412), відвантаження в рахунок авансу нової ПН не дає (Дт 70x Кт 643). Повернення авансу або неоплаченого товару дає РК на зменшення до останньої ПН; зміна ціни вгору дає РК на збільшення. Неплатнику ПН складається з типом причини 02.
- **ЄРПН**: статуси (складено, надіслано, зареєстровано, зупинено, пояснення подано, відмовлено), строки реєстрації за п. 201.10, штрафи за п. 120-1.1 зі ставками воєнного стану. РК на зменшення платнику реєструє покупець.
- **Вхідні ПН**: податковий кредит Дт 6442 Кт 6441 лише після реєстрації, зупинена ПН лишається на 6441.
- **СЕА ПДВ**: ліміт реєстрації за п. 200-1.3, електронний рахунок на субрахунку 315. ПДВ сплачується тільки через нього: Дт 315 Кт 311, далі Дт 6412 Кт 315. Пряма проводка Дт 6412 Кт 311 відхиляється.
- **Декларація**: чернетка рядків 1.1–21. Зобов’язання за датою першої події, кредит лише з зареєстрованих вхідних ПН.
- Дані ПН і РК для XML (форми J12010 і J12012) готує `toXmlData`; версію форми й теги беремо з чинної XSD ДПС під час експорту.
